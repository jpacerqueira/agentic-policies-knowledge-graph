- reads DevSecOps policy PDFs for the fictional Northline Bank plc (tier 1, 100000 employees)

## Runtime

The application runs only as Docker Compose project `policy-kg`. Containers `policy-kg-neo4j` and `policy-kg-app` share the dedicated bridge network `policy-kg-net`. Tests use `docker-compose.test.yml` and `policy-kg-test-net`.

## Run a new PDF

From `langgragh-sdk-app/`:

```bash
policy-kg run \
  --policy-dir data/policies \
  --oscal-dir data/oscal \
  --organization data/organization.json \
  --skip-neo4j \
  --report /tmp/policy-kg-run.json
```

The PDF must contain `POLICY-BLOCK-START` and `POLICY-BLOCK-END`. Exit 0 means the graph validated. Exit 1 means findings. Exit 2 means the command could not run (missing file or Neo4j).

## Intake page

`policy-kg serve` is the Python front end on port 8080. It accepts an http(s) policy link or an uploaded PDF. A policy block is used when the PDF has one. A sourced PDF without a block is split into statements and aligned to the loaded OSCAL catalogs, then optionally merged into Neo4j. Files land in `data/intake/`. The baseline scan reads only `data/policies/*.pdf`, so an imported file does not fail the sample run as `missing-policy-block`.

The running containers publish the page at http://localhost:8080.

## Intake, stored graph, and batch

The intake page accepts a drag-and-drop, a local folder, a policy link, or an S3 folder. Each submission run is a date-time directory under `submissions/`, bind-mounted into `policy-kg-app`. `policy-kg batch --from-dir` and `policy-kg batch --s3-uri` use the same folder. http://localhost:8080/graph lists the policies and the OSCAL ontology stored in Neo4j.

Skills for those runs:

- `test-batch-policy-pipeline` and `debug-batch-policy-pipeline`
- `test-interactive-policy-app` and `debug-interactive-policy-app`

## Submission folder name

The analysis folder is `submissions/`, mounted into `policy-kg-app` at `/app/submissions`. The container entrypoint serves with `--intake-dir submissions`. Each run stays in a date-time directory under that mount.
